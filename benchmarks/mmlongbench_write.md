# MMLongBench-Write

The MoDES heldout runner is `bench_modes_mmlongbench_evaluate.py --config <config.json>`. It accepts one policy per run: `methods=["modes"]` or `methods=["modes_tablemoe"]`. It reuses the completed calibration via `calibration_from` and keeps the original TableMoE split via `dataset_root` and `design2code_root`. It validates the checkpoint, calibrated runtime source, all 48 evaluation requests, existing baseline receipts, official rubric and VLMEvalKit sources before generation. Existing baseline, skip and TableMoE inference is not rerun. The baseline is read only for comparison.

MoDES generation uses FP16, hybrid eager execution, concurrency 4 and natural EOS with the same 8192-token ceiling and processor settings. After generation, the local BF16 Qwen judge runs sequentially on the configured GPU using the original native scoring protocol. `progress.json` distinguishes prediction from judging; `complete.json` becomes true only when all 48 scores verify. `comparison.json` reports native quality, length and overall scores plus the 1..5 Accuracy dimension. The reused baseline used offload graphs, so this run does not claim a paired performance result. The `artifacts/modes_mmlongbench_write_20261004_test48` run freezes its sources under `source_snapshot` and uses the completed 30-sample calibration targeting an overall 50% skip rate.

The combination run additionally requires the existing `pca_dir` and `cache_dir`; their manifest, checkpoint, processor, conversion policy and PCA bindings are checked before generation. Its Decode online/offline cosine thresholds are both 0.7. Default MoDES prefill skips table queries, and the runtime preserves original route weights without survivor renormalization. Optional `comparison_references` maps an explicit method label to a completed experiment root; all 48 request hashes and native scoring bindings must match. The combination's references are the completed pure MoDES run and `tablemoe_07` under the original experiment's `results/test_48`, rather than its legacy TableMoE result. Sources and outputs are isolated under `artifacts/modes_tablemoe_mmlongbench_write_20261004_test48`.

The separate `tablemoe_prefill_modes_tablemoe_decode` variant sets `modes_prefill_policy: "tablemoe"` with `methods: ["modes_tablemoe"]`. Its prefill retains 60% of active experts ranked per request/chunk, queries offline tables at vision/text cosine thresholds 0.6/0.7, and renormalizes surviving weights. Decode keeps the MoDES filter and 0.7 online/offline lookup without renormalization. This variant is distinct from both standalone TableMoE and the prior MoDES-prefill combination. Its frozen 48-sample run is under `artifacts/tablemoe_prefill_modes_tablemoe_decode_mmlongbench_write_20261004_test48`; references reuse baseline, pure MoDES, standalone `tablemoe_07`, and the prior combination without running their inference again.

Reusing calibration with this changed runtime requires `calibration_runtime_revision`: an exact map of calibration/evaluation hashes for every changed runtime file, a reason, and the hash/path of the variant's successful functional/Graph verification report. Missing, undeclared, or unvalidated changes fail. The experiment records both runtime identities and the original calibration provenance; it does not claim that calibration was refitted for the new prefill policy. Each run uses a fresh source snapshot and output directory.

Run `python benchmarks/bench_mmlongbench_write.py all --config artifacts/mmlongbench_write_20261002/config.json` in the existing FreeToken environment. The configuration specifies separate FreeToken, VLMEvalKit and vLLM interpreters. No dependencies are installed by the runner.

The pinned THU-KEG/LongWriter-V corpus has 120 examples in six contiguous 20-example task groups. Preparation uses seed 42 and selects 12 calibration and 8 test examples per task. Language strata also preserve the 60/40 ratio, and shared decoded-image groups stay together. The manifests retain all prompt text, original media order, sample IDs and image hashes.

The local VLMEvalKit checkout has no built-in MMLongBench-Write class. `mmlongbench_write.py` supplies a benchmark-side ImageBaseDataset extension, implements `build_prompt()` and `evaluate()`, and uses VLMEvalKit's native judge API. Its pinned official rubric includes all original images. Quality uses the six 1..5 dimensions; Accuracy is one dimension, not a classification percentage. Length and combined scores follow the official formulas. The local Qwen judge differs from the paper's GPT-4o judge, so scores are labelled accordingly. Missing predictions, unavailable judges and malformed grades fail the scoring stage.

All three modes use Qwen3-VL-30B-A3B-Instruct, FP16 expert weights converted explicitly from the BF16 checkpoint, greedy decoding and natural EOS with an 8192-token ceiling. Baseline computes all top-8 experts. Skip and TableMoE use the same prefill keep rate 0.6 and decode keep-k 4; skip disables both table queries and online maintenance and drops other routes. TableMoE uses its request-isolated online table. The experiment uses the GPU offload backend with identical 6144 expert slots and KV budgets across modes, and captures decode graphs through batch size 4.

One GPU collects actual full-expert prompt inputs and builds tables while the other can generate baseline and skip predictions. After construction, TableMoE prediction can overlap local vLLM judging on the other GPU. These concurrent inference durations are diagnostic rather than formal latency comparisons. The current rebuild is explicitly paused; changing its configuration does not resume it.

The builder uses the restored limits of 30000 vectors per layer/expert/modality and up to 1000 vectors per expert for PCA, saving 64-dimensional FP16 assets. The earlier 512-vector reservoir and 128-vector PCA overrides have been removed. K-means++ targets K=256, uses at most 30 iterations, and batches 8 experts in the paused configuration. Batched initialization is deterministic per expert but uses a different seeded sampling implementation from the scalar builder. Experts with fewer than 256 inputs use fewer prototypes; empty clusters are removed, and missing modality PCA coverage fails. Values are the unweighted FP16 expert forward at high-dimensional centroids. Collection snapshots own pinned memory, asynchronous D2H completes before the writer reads it, and stage hashes verify complete assets.

`build_time.json` records collection including service startup/shutdown and flushing, collection finalization and hash verification, PCA/clustering, materialization and their summed wall time. Raw predictions and judge responses, source/config fingerprints, split membership, asset manifests, CSV/JSON summaries and the rebuilt Markdown report remain in the experiment folder. A root `complete.json` is true only after all 72 calibration samples, all three sets of 48 predictions and all 144 judge evaluations complete. Interrupted collection resumes only at a verified completed-request boundary: ordered predictions, raw prefill/decode counts, all layer sampling counters and reservoir hashes must match. Inputs from unfinished requests require a fresh collection destination.

The generic all-token collector can include naturally generated decode inputs. MMLongBench-Write now explicitly selects `sampling_policy=tablemoe_default`, matching the prompt-only adaptive sampling method in `/home/fanya/tablemoe/offline_table/step1_profile.py`. Calibration runs one sample at a time, with an API completion limit of 1 to finish the prompt forward and obtain usage; that returned token is not a collected expert input. No decode inputs or reference answers are collected. The evaluation ceiling remains separately set by `natural_max_tokens` (8192 for the long-writing experiment). Canonical VLMEvalKit predictions are saved as `predictions.pkl` and checked for exact text round trips. XLSX is unsuitable for these predictions: some actual 8192-token answers exceed its 32767-character cell limit.

The completed baseline/skip inference and later scoring can have separate source epochs when a scoring-only issue is repaired. The run retains each original manifest and the changed source files, and records an explicit migration only after verifying that inference sources, request generation, model commands and judge calls are unchanged. Original per-mode stage manifests remain intact; an existing stage from a different source epoch is not silently reused by the runner.

The paused rebuild configuration uses per-sample vision bounds 1..64 and text bounds 8..128. Its 100000 vision and 40000 text token budgets are upper limits, not targets or minimum coverage requirements. The adaptive quota is the rounded remaining budget per remaining sample, multiplied by the square root of the current candidate length divided by the median previous candidate length, then clamped to the per-sample bounds, available positions and remaining budget. Positions are sampled without replacement with seed 42 in calibration manifest order; masks are shared across all layers and prefill chunks. A checkpoint of the RNG, histories, quotas and selected prompt positions supports validated continuation. With 72 samples the absolute upper bounds are 4608 vision positions and 9216 text positions. Short prompts may contribute fewer. The original split's RNG shuffle is not reused, since this benchmark preserves its separate category-stratified 60/40 manifest.

Only selected rows are copied to CPU and retained as raw FP16 expert inputs; full prompt candidate counts and selected counts are recorded separately. Raw inputs are read directly for clustering instead of creating duplicate exported input files. Completed runs remove step1 vectors after verification of cache and PCA assets, retaining collection manifests, sampling counts and timings. On the user's explicit pause-and-delete request, the rejected full-text collection and earlier raw input stores were removed immediately, before any new table was produced. Their metadata remains in `rejected_sampling_record/`, and `paused_raw_input_cleanup.json` lists the deleted paths. No corrected collection, table or accuracy result has been produced yet.

Collection groups routes with NumPy and reuses unbuffered file handles. Append-only inputs update SHA-256 incrementally, while reservoir replacements invalidate that incremental digest and use a full file hash. Resuming rebuilds each digest from verified files, and finalization still verifies every full file. Earlier collection epochs and their elapsed times remain diagnostic records of the rejected sampling protocol. A future corrected run needs a fresh output directory and manifest; it cannot reuse those raw inputs or claim their timing as a completed corrected build.
